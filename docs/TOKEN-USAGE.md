# Токен зарцуулалт ба session удирдлага

**2026-09-15.** Fable 5.1-ийн долоо хоногийн хязгаарт тулсны дараа бодитоор
хэмжиж гаргасан шалтгаан, засвар, ажиллах дүрэм. Тоонууд таамаг биш — файлын
бодит хэмжээ (`wc -c`), 1 токен ≈ 3 байт (кирилл, UTF-8) гэж тооцов.

---

## 1. Хамгийн том эх үүсвэр — гарын авлага session бүрт дахин ачаалагддаг байсан

`CLAUDE.md` нь `@docs/PROJECT-GUIDE.md`-ийг импортолдог тул тэр файл **session
бүрийн эхэнд БҮТНЭЭР** контекстэд ордог. Мөн context дүүрч **compact хийгдэх
бүрд дахин бүтнээр** ачаалагддаг.

| | Өмнө | Одоо |
|---|---|---|
| `docs/PROJECT-GUIDE.md` | 165 KB ≈ **55,000 токен** | 36 KB ≈ **12,000 токен** |

Нэг урт session-д 4 удаа compact хийгддэг гэж үзвэл: 55,000 × 5 = **275,000
токен**, зөвхөн нэг ижил файлыг дахин дахин уншихад. Одоо 60,000 — **долоо
хоногийн хязгаарын мэдэгдэхүйц хувийг ганцхан энэ засвар чөлөөлнө.**

**Юу хийсэн бэ:** 123 KB-ийн өнгөрсөн session-ий тэмдэглэлийг бүрэн эхээр нь
[HISTORY.md](../HISTORY.md)-рүү зөөв (гарчиг бүр яг ижил нэртэй, хайлтаар олдоно).
Гарын авлагад зөвхөн **дүрэм, тохиргоо, идэвхтэй ажил** үлдсэн.

> ⛔ **Дүрэм:** шинэ session-ий тэмдэглэл, аудитын тайлан, "юу хийсэн" түүх
> ХЭЗЭЭ Ч PROJECT-GUIDE.md-д бичигдэхгүй — HISTORY.md-д бичнэ. Гарын авлагад
> зөвхөн дараагийн session мэдэх ёстой **дүрэм** нэмэгдэнэ, 1-2 мөрөөр.

## 2. Дараагийн эх үүсвэр — том файлуудыг бүтнээр унших

| Файл | Хэмжээ | Бүтнээр уншвал |
|---|---|---|
| `server/db.ts` | 355 KB | ≈ 118,000 токен |
| `server/routers.ts` | 224 KB | ≈ 75,000 токен |
| `shared/i18n.ts` | 131 KB | ≈ 44,000 токен |
| `client/src/components/AdminWorkspace.tsx` | 90 KB | ≈ 30,000 токен |

Нэг файлыг бүтнээр уншвал бүтэн session-ий төсөв алга болно.

⚠️ **`client/src/pages/Checkout.tsx` онцгой урхи:** JSX нь НЭГ асар урт мөр тул
`grep` хийхэд 42 KB-ийн ганц мөр буцдаг. Тэнд заавал `cut -c1-200` эсвэл
`-o` (зөвхөн таарсан хэсэг) ашиглана.

**Дүрэм:**
- Grep tool-д `head_limit` заавал (анхдагч 250 мөр ч гэсэн их).
- Read tool-д `offset` + `limit` — `sed -n '4380,4400p'` маягаар зөвхөн хэрэгтэй мужаа.
- Bash-ийн гаралт бүрийг `| head -N`, `| tail -N`, `| grep -E "..."`-ээр таслах.
- Файл засварласны дараа **буцааж уншихгүй** — Edit алдаа гарвал өөрөө шидэнэ.
- `cat` том файл дээр хэзээ ч бичихгүй.

## 3. Бусад бодит эх үүсвэрүүд

**Playwright (хөтөч).** `browser_navigate` бүр хуудасны бүтэн accessibility
snapshot буцаадаг; `browser_take_screenshot` `fullPage: true` үед 7,500px өндөр
зураг үүсдэг бөгөөд түүнийг уншвал зураг бүр мянган токен. **Дүрэм:**
шалгалтаа `browser_evaluate` дотор хийж, **жижиг JSON** буцаа (overflow, h1
тоо, алдааны тоо). Зураг зөвхөн дизайн БОДИТООР харах шаардлагатай үед, viewport
хэмжээгээр.

**Тест, build.** Бүрэн suite (935 тест) ойролцоогоор 9 минут, гаралт нь урт.
**Дүрэм:** ажиллаж буй файлынхаа тестийг л ажиллуул; бүрэн suite-ийг зөвхөн
deploy-ийн өмнө, `| Select-Object -Last 15`-тэй.

**Урт paste.** Чатанд HTML, лог, CSV-г бүтнээр буулгах нь тэр агуулгыг session
дуустал контекстэд үлдээнэ. **Дүрэм:** файлд хадгалаад **замыг нь** өг —
`C:\\...\\log.txt` гэж бичвэл хэрэгтэй хэсгийг нь л уншина.

**Давхардсан ажил.** Кодыг эхлээд шалгалгүй "шинэ функц" бичиж эхэлбэл (жишээ
нь 09-14-нд урсдаг зар аль хэдийн байсныг мэдэлгүй дахин хийж эхэлсэн) бүх
токен дэмий үрэгдэнэ. **Дүрэм:** барихаасаа өмнө `grep` — 2 минутын шалгалт
20 минутын ажлыг аварна.

## 4. Аль загварыг аль ажилд — Tom-ийн дүрэм

> **"Fable-ийг зөвхөн ТӨЛӨВЛӨХ, ШАЛГАХАД. Sonnet, Opus-ийг ХИЙХЭД."**
> (Tom, 2026-09-15)

Хязгаар нь загвар тус бүрээр тооцогддог тул хамгийн үнэтэй загвараар бүх ажлыг
хийлгэх нь долоо хоногийн эрхийг дэмий шатаана. Хамгийн үнэтэй нь бодох ажил,
хамгийн хямд нь бичих ажил байх ёстой.

| Ажил | Загвар |
|---|---|
| Төлөвлөх: шинэ feature, редизайн, архитектур, "яаж хийх вэ" | **Fable** |
| Шалгах: diff унших, аудит, "энэ зөв үү", deploy-ийн өмнөх хяналт | **Fable** |
| Хийх: код бичих, засах, тест, CSS, орчуулга, refactor | **Sonnet / Opus** |
| Хайх: файл олох, лог шалгах, "хаана байна" | **Haiku** |

Солих: `/model sonnet`, `/model opus`, `/model fable`. Ажлын дунд ч солино.

### Subagent-ууд (загвар нь бэхлэгдсэн)

`.claude/agents/` дотор дөрвөн agent тодорхойлогдсон. Тэдгээр нь **зөвхөн
дуудагдсан үедээ** контекст эзэлдэг тул session эхлэхэд үнэгүй:

| Agent | Загвар | Үүрэг | Засварлах эрх |
|---|---|---|---|
| `planner` | fable | Судалж, алхам гаргана | ❌ |
| `verifier` | fable | Diff шалгаж, зөрчил мэдээлнэ | ❌ |
| `builder` | sonnet | Кодыг бичнэ | ✅ |
| `scout` | haiku | Файл, мөр олно | ❌ |

Яагаад ашигтай вэ: subagent нь **яриа бүхэлдээ биш**, зөвхөн өгсөн даалгавраа
хүлээн авдаг. Өөрөөр хэлбэл 200 мессежийн түүхийг дахин уншихгүйгээр ажлаа
хийнэ. Урт session-ий дунд "энэ файлыг ол" гэж scout-д даалгах нь өөрөө хайхаас
хямд.

⚠️ Subagent бүр өөрийн контексттэй тул **олон субагент зэрэг дуудах нь ч үнэтэй**
— үнэхээр тусдаа ажил байвал л дуудна.

## 5. Session удирдлага (Tom-д)

1. **Нэг session = нэг ажил.** "Careers хуудас" дуусмагц шинэ session. Урт
   session-д өмнөх ажлын бүх мөр дахин дахин уншигдана.
2. **`/compact` гараар эрт дууд.** Автоматаар дүүртэл хүлээвэл хамгийн үнэтэй
   үед (бүх контекст дүүрэн байхад) хийгддэг.
3. **`/clear`** — сэдэв бүрэн солигдох үед (жишээ нь танилцуулгаас кодруу).
4. **Нэг мессежинд нэг зорилго.** "Үүнийг хий, тэрийг ч бас, бас энэ" гэвэл
   бүгдийг нэг контекстэд барих шаардлага гарна.
5. **Screenshot зөвхөн хэрэгтэй үед.** Дизайн харуулах бол тийм; лог харуулах
   бол текстээр буулга.
6. **Хийж дуусаагүй ажлыг session хооронд орхихгүй** — commit хийж, HISTORY.md-д
   нэг мөр бичээд дуусга. Дараагийн session тэр мөрийг уншаад л үргэлжлүүлнэ.

## 6. `.claude/settings.json` (үүсгэсэн)

- `includeCoAuthoredBy: false` — commit-д AI attribution нэмэхгүй (Tom-ийн дүрэм).
- `permissions.allow` — зөвхөн уншдаг командууд (git status, grep, ls, sed, тест,
  build) зөвшөөрөл асуухгүй. Зөвшөөрөл асуух бүрт ажил тасарч, дахин эхлэхэд
  контекст дахин уншигддаг.
- `permissions.deny` — `.env`, `*.pem` уншихыг хориглов; `rm -rf`, `git push
  --force` мөн.
- `cleanupPeriodDays: 30` — хуучин transcript автоматаар цэвэрлэгдэнэ.

## 7. Хэмжих

Гарын авлага дахин томорч эхлэвэл шалгах:

```bash
wc -c docs/PROJECT-GUIDE.md docs/CODEBASE.md   # 40 KB-аас хэтэрвэл HISTORY.md рүү зөө
```

Session дотор `/context` команд одоогийн контекст хэдэн хувь дүүрснийг харуулна.
