## 1. Арга: үнийг ДАРЖ БИЧИХГҮЙ, "хямдралын үйл явдал" давхарга

**Сонгосон (санал):** шинэ `price_campaigns` хүснэгт. Хямдрал идэвхтэй үед
сервер үнэ уншдаг бүх газарт `priceMnt`-ийг хямдруулсан үнээр, `compareAtPriceMnt`-ийг
анхны үнээр СОЛЬЖ буцаана. DB-ийн үнэ хэвээр үлдэнэ.

Яагаад:
- **Эхлэх/дуусах цаг автомат**, яг минутад. Шөнө 00:00-д хэн нэгэн товч дарах шаардлагагүй.
- **Зогсооход юу ч сэргээхгүй** — анхны үнэ хэзээ ч өөрчлөгдөөгүй.
- Клиентийн карт, сагс, барааны хуудас одоо байгаа зураастай үнэ ба "-X%"-ийг
  **өөрчлөлтгүйгээр** харуулна (сервер ижил хоёр талбарыг өгнө).
- Хямдралын үеэр Tom барааны үнэ сольж болно, Smart Software үнэ татаж болно — мөргөлдөхгүй.

**Татгалзсан — А арга (984 барааны үнийг шууд дарж бичээд дараа нь буцаах):**
хоёр хүснэгтэд бичих ёстой, буцаах snapshot хэрэгтэй, хямдралын үеэр гараар
засвал буцаалт түүнийг арчина, вендорын үнэ татахад хямдрал алга болно, эхлэх/дуусах
цагт хэн нэгэн товч дарах ёстой.

## 2. Tom-ийн шийдэх 6 асуулт (санал болгож буй анхдагчтай)

| # | Асуулт | Санал |
|---|---|---|
| 1 | Аль бараанд? | **Бүх бараа** (бэлгийн карт үргэлж хасагдана). Дараагийн үе шатанд ангилал/брэндээр сонгох боломж |
| 2 | Аль хэдийн хямдралтай (хуучин үнэтэй) барааг яах вэ? | **Алгасах** — давхар хямдрал өртгөөс доош унах эрсдэлтэй. Сонголтоор "тэдэнд ч хэрэглэх" |
| 3 | Купон, гишүүнчлэлийн хямдрал, routine багц дээр нь нэмэгдэх үү? | **Тийм, одоогийн дарааллаар** хямдарсан дүн дээр тооцогдоно. Сонголтоор "хямдралын үеэр купон ажиллахгүй" |
| 4 | Дэлгүүрийн касс (POS) болон утсаар авсан гар захиалгад хэрэглэх үү? | **Зөвхөн онлайн** (касс тавиурын шошгын үнээр). Гар захиалгад — **тийм** (харилцагч сайт дээрх үнийг хэлнэ) |
| 5 | Үнийг хэрхэн бөөрөнхийлөх вэ? | **100₮ хүртэл доош** (29 900 × 0.8 = 23 920 → 23 900). Анхны үнээс хэзээ ч өндөр болохгүй |
| 6 | Хэн асааж/унтрааж болох вэ? | **Зөвхөн admin** — мөнгөний шийдвэр |

## 3. Хэрэгжүүлэлт — 5 үе шат

### Үе шат 1 — өгөгдөл ба цэвэр тооцоо
- Migration `0096_price_campaigns.sql` (prod + `sugi_staging` хоёуланд):
  - `price_campaigns`: `id`, `name`, `percentOff` (1–90), `scope` (`all` | `category` | `brand`),
    `scopeValue`, `skipAlreadyDiscounted`, `stackWithCoupons`, `appliesToPos`,
    `appliesToManualOrders`, `roundingMnt` (1/10/100), `startsAt`, `endsAt` (заавал),
    `stoppedAt`, `createdByUserId`, `createdAt`, `updatedAt`.
  - `orders.priceCampaignId` (nullable, SET NULL) ба `order_items.listPriceMnt`
    (nullable) — "хямдралаар хэдэн төгрөг хөнгөлсөн" тайлангийн тулд.
- `shared/price-campaign.ts` (цэвэр, клиент ба сервер хуваалцана):
  `isCampaignLive(c, now)`, `campaignPrice({ priceMnt, compareAtPriceMnt, kind }, c)`
  → `{ priceMnt, compareAtPriceMnt }`. Дүрэм: бэлгийн карт хөндөхгүй; хуучин үнэтэй
  барааг `skipAlreadyDiscounted` үед хөндөхгүй; бөөрөнхийлөлт доош; 0₮-өөс бага,
  анхны үнээс их хэзээ ч биш.
- `server/db/price-campaigns.ts` (barrel-д нэм): CRUD, `getLiveCampaign()` — 30 с
  кэш + бичих бүрт `invalidateCached`, давхцсан хоёр хямдрал байж болохгүй (сервер
  татгалзана), эхлэх/дуусах цагийг кэш биш хүсэлт бүрт `now`-оор шалгана.

### Үе шат 2 — үнэ уншдаг бүх газарт холбох
Нэг туслах `applyLiveCampaign(rows)` — кэшээс уншсаны ДАРАА хэрэглэнэ (кэш
түүхий үнэ хадгална, тиймээс эхлэх/дуусах мөчид 60 с хоцрохгүй):
- `catalog.ts`: `getPublishedCatalogPage` (үнийн шүүлт ба эрэмбэлэлтээс ӨМНӨ),
  `getPublishedProductsByIds`, `getBestsellingProducts`, `getRelatedProducts`,
  `getFrequentlyBoughtTogether`, `getRecommendedProducts`, `getProductBySlug`,
  `getPublishedProductBySku`, хайлтын үр дүн.
- Variant сонгогчийн public жагсаалт (`variants.ts`).
- Сагс `getActiveCartForOwner` → cart drawer ба checkout-ийн урьдчилсан тооцоо ижил үнэ.
- `createOrderFromActiveCart`: хямдралыг транзакцын эхэнд НЭГ удаа уншиж, мөр бүрт
  `unitPriceMnt` = хямдарсан, `listPriceMnt` = анхны, захиалгад `priceCampaignId`.
  Routine багцын хямдрал хямдарсан үнээр тооцно; купон/гишүүнчлэл §2-3-ын шийдвэрээр.
- **Checkout-ийн хамгаалалт:** клиент харсан нийт дүнгээ (`expectedTotalMnt`)
  илгээнэ; хямдрал яг тэр минутад дуусч дүн өөрчлөгдвөл сервер захиалга үүсгэхгүй,
  "Үнэ шинэчлэгдлээ, дахин шалгана уу" гэнэ (өндөр үнээр чимээгүй авахгүй).
- POS ба гар захиалга — §2-4-ийн шийдвэрээр.
- Google merchant feed: `sale_price` + `sale_price_effective_date`; барааны JSON-LD үнэ.
- Захиалга засах (`editAdminOrder`) хуучин мөрийн үнийг хэвээр үлдээнэ (одоогийнх шиг).

### Үе шат 3 — /admin дэлгэц
- "Урамшуулал" хэсэгт **"Нийтийн хямдрал"** карт (шинэ admin хэсэг нээхгүй — байршлыг Tom батална).
- Талбар: нэр, хувь, эхлэх/дуусах огноо-цаг (Улаанбаатарын цагаар, `toDayInput` дүрэм),
  §2-ын сонголтууд.
- **Урьдчилан харах:** хэдэн бараанд хамаарах, хэд нь алгасагдах (хуучин үнэтэй /
  бэлгийн карт), 5 жишээ бараа "29 900₮ → 23 900₮", хамгийн бага үнэ,
  өртөг (`costMnt`) мэдэгдэж байгаа бараанаас өртгөөс доош унах жагсаалт.
- "Эхлүүлэх" ба "Одоо зогсоох" — `useConfirm()` баталгаатай; аудитын лог
  (`price_campaign.created/updated/stopped`); өмнөх хямдралуудын түүх.
- Сонголтоор: хямдрал эхлэхэд сайтын баннер (`site_promotions`) автоматаар асаах.

### Үе шат 4 — тайлан
- Analytics: хямдралын үеийн борлуулалт, хөнгөлсөн дүн
  (`Σ (listPriceMnt − unitPriceMnt) × quantity`, `settledSaleSql`-ээр л), захиалгын тоо,
  хямдралын өмнөх ижил хугацаатай харьцуулалт.

### Үе шат 5 — тест ба баталгаажуулалт
- Unit: `campaignPrice` (бөөрөнхийлөлт, 0/анхны үнийн хязгаар, бэлгийн карт,
  хуучин үнэтэй бараа), `isCampaignLive` (эхлэх/дуусах мөч, Улаанбаатарын цаг).
- Integration (`sugi_staging`): идэвхтэй үед каталог/сагс/checkout хямдарсан үнээр
  тооцно, дууссаны дараа анхны үнээр; `expectedTotalMnt` зөрвөл татгалзана; купон
  стек; POS дүрэм; давхцсан хямдрал татгалзана; `forgetSessionUser` шаардлагагүй
  (users-д бичихгүй).
- E2E: admin 20% хямдрал үүсгэнэ → /shop карт зураастай үнэ ба "-20%" → сагс →
  checkout нийт дүн таарна → зогсооно → анхны үнэ. Компьютер + утас хоёуланд.
- Хөтөч дээр screenshot (1366 ба 390 өргөн) — карт, барааны хуудас, сагс, admin карт.
- `pnpm check`, `pnpm lint`, `pnpm build` (exit code шууд), бүтэн `pnpm e2e`.
